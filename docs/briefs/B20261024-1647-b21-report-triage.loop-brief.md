# Brief — vloop B21: report a vloop defect upstream, triage it here

- **Starting point:** extends `main` at `bacb262` (v0.12.0). The planner pins
  that SHA as the **base** every gate compares against — never `HEAD~n`.
- **Produced by:** issue #50 (operator-initiated feedback from the repositories
  that use vloop) and the design act of 2026-10-24, after the first field
  report: #53, a session record that kept the macOS temp directory, found in a
  target repository, filed by hand, then recorded here by hand as an escape of
  B8.

## Executive summary

Defects in vloop are found in two places: in vloop's own runs, where they are
recorded in `.vloop/defects/`, and in the repositories vloop runs in, where
today they reach vloop only when the operator writes an issue by hand. #53 took
four manual steps and two masking edits; its path had to be cut by hand before
the issue was public.

**The goal:** a vloop defect found in any repository becomes a GitHub issue the
operator approved, with nothing private in it, and here it becomes an escape
counted against the brief it came from, linked to its issue.

- **L1 — defects and interventions link to their issue.** `defect/v2` and
  `intervention/v3` carry an `issue`; a defect can be dated when it was found.
- **P1 — a privacy check for a draft.** `vloop report check` refuses a draft
  that names the machine, the user, a secret or the repository it came from.
- **R1 — `/vloop:report` drafts the issue and files it only on the operator's
  yes**, then links the issue to the intervention that triggered it;
  `/vloop:operate` suggests it once at the end of a run.
- **T1 — triage here.** This repository's playbook turns an issue into an
  escape: origin brief and task, origin and kind, the issue linked, the issue
  answered.
- **F1 — a brief named any way counts all its defects and interventions.**
  `vloop metrics <brief>` and `--brief` filters give the same records for
  the bare name, the `.loop-brief` name and the path.

Unchanged: defects found in a target repository's own code stay in that
repository's `.vloop/defects/`; no session ever files anything; the binary
never touches the network.

## Why this shape, and what was rejected

Decided with the operator on 2026-10-24. **Do not re-litigate these** — the
planner inherits them.

- **Issues for what is found elsewhere, records for what is measured here.**
  A vloop defect found in a target repository is reported as an issue on
  vloop's repository; once triaged here and found to be an escape of a brief, it
  is also recorded in `.vloop/defects/`, linked to the issue. Defects found in
  vloop's own runs are recorded as today. The record stays the measure: M-4
  counts escapes from records, offline and versioned.
  *Rejected:* dropping `.vloop/defects/` for issues (escape counting would need
  the network and a token, and the records' fields would become label
  conventions); issues only for field reports with no record (the escapes users
  find would never count, and the escape rate drifts to zero).
- **One brief for both halves.** Report and triage share the link and its
  records; one contract for the whole path.
  *Rejected:* two briefs, which design the issue link twice.
- **The link is a new schema version.** `defect/v2` adds `issue`, as
  `intervention/v3` does; a record's schema says what it contains. Readers keep
  accepting `defect/v1` and `intervention/v2` (and v1), which have no issue.
  *Rejected:* adding the field to v1 in place (C-3 allows it, but a v1 record
  would then mean two things); the issue in the summary text, as #53's record
  has it (not machine-readable).
- **Filing is always the operator's act, as #50 sets it.** A skill drafts,
  checks and shows the full text; it files only after the operator says yes to
  that text, every time. It never files on the strength of a gate, a review or
  another session's output.
- **The privacy check is a command, not a rule in the skill.** A skill's
  judgement leaves out project names and code; a deterministic check refuses
  what a reader can miss — #53's path was one.
  *Rejected:* relying on session masking; it masks what sessions print, not a
  draft written from many sources, and it missed the temp directory (#53).
- **The binary never calls GitHub.** `gh` is run by the skills, in the
  operator's interactive session; the binary stores references and dates it is
  given.
  *Rejected:* `vloop defect add --from-issue`, which would make the binary
  depend on the network and a token.

## Behaviour contract

### L1 — the issue link

- An issue reference is `<owner>/<repo>#<n>` or a GitHub issue URL (the
  `github.com/<owner>/<repo>/issues/<n>` page, over https); it is stored as
  `<owner>/<repo>#<n>`. Anything else is refused:
  `vloop: invalid issue "<value>": want <owner>/<repo>#<n> or a GitHub issue URL`,
  exit 2, nothing written.
- `vloop defect add … --issue <ref>` and `vloop defect set <id> issue <ref>`
  set it. `vloop defect add … --found <RFC 3339 time>` sets `created` to when
  the defect was found (the issue's opened time); it is refused when in the
  future or not RFC 3339, exit 2. Without `--found`, `created` is now, as today.
- Every record `defect add` writes is `defect/v2`: all of `defect/v1`, plus
  `issue` (empty when none), with `schema: defect/v2` in its frontmatter. A
  defect file with no `schema` line is `defect/v1`, as every record today is.
  `vloop defect set` on a v1 record writes it back as v1 unless the field set is
  `issue`, which makes it v2.
- `vloop intervention add … --issue <ref>` and `vloop intervention set <id>
  issue <ref>` do the same for interventions; new records are `intervention/v3`,
  and `vloop intervention migrate` brings older ones to v3 with an empty issue.
- `vloop defect list` and `vloop intervention list` show the issue as one more
  column (`-` when none); `--json` carries `issue`. schemas/defect.v2.json and
  schemas/intervention.v3.json validate them; `vloop schema validate` knows
  both. `vloop metrics`, `export` and `brief close` read v1, v2 and v3 alike.

### P1 — `vloop report check <file>`

Reads a draft and reports every finding, not only the first:

- `absolute path` — the home, the repository root's absolute path, the system
  temp directory (`os.TempDir()`, with `/private` resolved on macOS), or any
  path whose first two components are a users directory (`Users` or `home`)
  and a name, or a Windows drive's `Users` and a name, in both slash forms;
- `user name` — the user name as a whole word, case-insensitive;
- `secret` — the value of any secret-named environment variable, as
  `redactSecrets` defines them;
- `repository name` — the repository root's directory name, and the
  `<owner>/<repo>` of its `origin` remote, as whole words.

Output: findings on stderr as `report: <file>:<line>: <kind>: <fragment>`, then
exit 1. A clean draft prints `report: clean`, exit 0. `--allow <word>`
(repeatable) accepts a word the operator decided may appear, such as a public
repository's name; it never allows a secret. A missing or unreadable file is
exit 2. The check reads only the draft, the environment and the repository's
git config; it never runs a network command.

### R1 — `/vloop:report` and the end-of-run suggestion

- A new plugin skill, `/vloop:report [<intervention or halt id>]`, for an
  interactive session only:
  1. Decides with the operator whether the problem is vloop's or the
     repository's. A repository's own defect is recorded there as today, and the
     skill stops.
  2. Drafts the issue in `.vloop/tmp/` in #50's shape: a privacy line first; what
     happened, with `vloop version --json`, the config values that matter and the
     exact output lines; why it matters; a proposal; related issues. Project
     details are described generically.
  3. Runs `vloop report check` on the draft until it is clean, using `--allow`
     only for a word the operator approves by name.
  4. Shows the full text and files it with `gh issue create --repo
     mvelosop/vloop` only after the operator says yes to that text.
  5. Links the issue: `vloop intervention set <id> issue <ref>` on the
     intervention that triggered it, or a new `carry-forward` intervention when
     none did.
- `/vloop:operate`, at the end of a run after close, lists once the candidates
  that point at vloop rather than at the brief or the repository —
  interventions with `automatable` `yes` or `partly`, `carry-forward` ones,
  halts — and asks whether to draft issues for any of them. It does nothing
  more without a yes.

### T1 — triage in this repository

`.claude/skills/vloop-operator/SKILL.md` gains a triage section: for an issue on
this repository,

1. reproduce or confirm it from the evidence;
2. find the origin: `vloop defect add --blame <file>:<line>` for a line that
   does the wrong thing, or the brief whose contract set the behaviour (as F11 in
   B8 set #53's), with the task when one did it;
3. set `origin` and `kind` by `docs/domain/measurement/defect.md`'s axes
   (`brief`/`spec-gap` when the contract was wrong or silent);
4. record it with `--issue <ref> --found <the issue's createdAt>` and
   `--found-by user` when it was found after release;
5. comment on the issue with the defect id, after the operator approves the
   comment.

Issues that are not escapes (enhancements, a brief not yet merged) get no
record.

### F1 — a brief named any way

**Defect.** `vloop metrics B20261002-2135-vloop-v1-security` prints 3 defects
and 0 interventions; `vloop metrics B20261002-2135-vloop-v1-security.loop-brief`
prints 9 and 3. The bare name finds the brief's runs, so the numbers look
plausible, but every recorded defect and intervention is dropped: their
`brief:` field carries `.loop-brief`, and the lists compare it to the name as
given. `vloop defect list --brief <bare name>` prints nothing.

**Required.** Every command that takes a brief — `vloop metrics <brief>`,
`vloop defect list --brief`, `vloop intervention list --brief`, `defect add
--brief`, `intervention add --brief` — treats the bare name, the `.loop-brief`
name and the path `docs/briefs/<name>.loop-brief.md` as the same brief, and
records stay written with the `.loop-brief` name, as now.

**Gate.** On this repository's history: the three forms give equal `defects`
and `interventions` in `vloop metrics --json` for B8, and equal output for
`defect list --brief`. It fails on the base.

### Decided here, because the cited documents leave it underdetermined

- Issues go to `mvelosop/vloop`, named in the skill; a fork that wants its own
  edits the skill.
- `found-by` stays as M-4 has it: an issue found after release is `user`,
  whoever filed it.
- `--found` dates the record; M-4's "created after the release commit" reads
  that date. A defect found before release but triaged after it is not an
  escape.
- `vloop doctor` does not check `gh`; the skill says what to do when `gh` is
  missing or not logged in.

### Violations the review must rule on

- Any path where a skill files an issue, or posts a comment, without the
  operator's yes to that exact text.
- A privacy check that passes a draft containing any planted finding of the
  worked example, or that `--allow` can make pass with a secret in it.
- The binary running `gh`, `curl` or any network call.
- A `defect/v1` or `intervention/v2` record that a reader no longer accepts.
- F1 fixed in `vloop metrics` only, leaving a `--brief` filter dropping records.

## Worked example

Defects and issues, in this repository:

```
vloop defect add "temp directory unmasked" --brief B20261002-2135-vloop-v1-security.loop-brief \
    --task T8 --origin brief --kind spec-gap --found-by user --severity low \
    --issue mvelosop/vloop#53 --found 2026-10-24T15:02:00Z
  -> .vloop/defects/D<stamp>-temp-directory-unmasked.md                  exit 0
     frontmatter: schema-valid as defect/v2, issue: mvelosop/vloop#53,
     created: 2026-10-24T15:02:00Z

vloop defect add "x" --brief <same> --issue 53
  -> vloop: invalid issue "53": want <owner>/<repo>#<n> or a GitHub issue URL   exit 2

vloop defect add "x" --brief <same> --found 2099-01-01T00:00:00Z
  -> refused, nothing written                                             exit 2

vloop metrics B20261002-2135-vloop-v1-security --json      (bare name)
vloop metrics B20261002-2135-vloop-v1-security.loop-brief --json
vloop metrics docs/briefs/B20261002-2135-vloop-v1-security.loop-brief.md --json
  -> the same "defects" and "interventions" objects, all three           exit 0
     (the gate threads the counts it reads; it does not hardcode 9 and 3)
```

The privacy check, in a fixture repository at `<home>/src/acme-billing`,
where `<home>` is a users-directory path ending in `ana` that the fixture
creates under its temporary directory, with `HOME=<home>`, `USER=ana`, origin `git@github.com:acme/acme-billing.git`,
`GITHUB_TOKEN=ghp_fixture123`, a temp directory set by `TMPDIR`, and a draft
with one planted finding per line:

```
vloop report check draft.md
  -> report: draft.md:3: absolute path: <home>/src/acme-billing/.vloop/state
     report: draft.md:4: absolute path: <TMPDIR>/refimpl.x1
     report: draft.md:5: user name: ana
     report: draft.md:6: secret: ghp_fixture123
     report: draft.md:7: repository name: acme-billing
     report: draft.md:8: repository name: acme/acme-billing                exit 1

vloop report check draft.md --allow acme-billing --allow acme/acme-billing
  -> the first four lines only                                            exit 1

vloop report check draft.md --allow ghp_fixture123
  -> still reports the secret                                             exit 1

vloop report check clean.md        (repo-relative paths, vloop version, no names)
  -> report: clean                                                        exit 0
```

A record written by the base binary (`defect/v1`, `intervention/v2`) still
validates, lists and counts the same with the changed binary.

## Out of scope

- The fix of #53 itself (masking the temp directory in session records); it is
  on its own branch.
- Labels, assignees or projects on issues; syncing an issue's state with a
  defect's `status`.
- Any binary command that reads or writes GitHub (`--from-issue`, `defect
  sync`).
- Reporting from a loop session, or automatically at any point.
- Issue trackers other than GitHub.
- An eval suite for `/vloop:report`; the structural checks cover it in this run.
- Retiring or migrating `defect/v1` and `intervention/v2` records.
- A `doctor` check for `gh`.

## Constraints

- Go, at the version in `go.mod`; no new dependencies.
- Must keep building and passing on macOS, Linux and Windows; the privacy check
  is tested on every OS, its path forms as pure functions.
- **No gate touches the network**, and no gate runs `gh`.
- Tests build fixtures in temporary directories and address them with `git -C`;
  sessions never move refs.
- **Gates follow the diff surface.** Each task gates on what it touches; no task
  runs the whole test suite.
- **No task may weaken a check to pass.** An earlier test changes only where it
  pins behaviour the contract changes, and only to the new behaviour; the work
  session names the contract item in its notes and the review cites it.
- **New tooling is proven by fixtures**, including where it must fail: every
  planted finding of the worked example, an `--allow` that must not allow a
  secret, a bad issue reference, a future `--found`.
- Repo-relative paths everywhere. No absolute paths in any file or commit
  message.

## Shape

6 to 7 tasks, each verifiable by a single command. Order is load-bearing:

1. **F1 — a brief named any way**, with the real-data check on B8. Gated on the
   three forms agreeing, which fails on the base.
2. **L1 for defects — `defect/v2`, `--issue`, `--found`, `set issue`**, readers
   for v1. Gated on the worked example's defect lines and schema validation of
   v1 and v2 records.
3. **L1 for interventions — `intervention/v3` and `--issue`.** Gated likewise.
4. **P1 — `vloop report check`**, with the fixture repository. Gated on the
   worked example's check lines.
5. **R1 — `/vloop:report` and the operate suggestion.** Gated on the structural
   skill checks. Prose task: if it fails review twice on wording, block it and
   the operator finishes it.
6. **T1 and the docs** — the triage section, `docs/guide/defects.md`, the defect
   domain page and the command reference. Prose task, as above.
7. **Close:** every gate at once, and the worked example line for line.
