# Brief — vloop B11: the quality pass

- **Starting point:** extends `main` after the v2.0.0-beta.2 release
  (`27871b2`, tag `v2.0.0-beta.2`) and the upgrade to it (`630b12d`, PR #19).
  The planner pins the base it plans from as the **base** every gate compares
  against — never `HEAD~n`.
- **Produced by:** the design act of 2026-10-05, from
  `docs/design-notes/vloop-v2.0-roadmap.md` → "B11", with every finding of
  `docs/design-notes/vloop-v1-review.md` → "B9 — quality" re-checked against the
  base by an independent survey, and the forks settled with the operator
  (intervention recorded with this brief).
- **Run by:** `vloop run` from the released v2.0.0-beta.2.

## What it is

A newcomer who reads the README cannot install vloop or make a first run; a
script cannot tell a typo from a failure, because 84 errors exit 2; the help says
nothing about what a brief is; the guides still describe v1 in places; and
`defect set` on a CRLF record does nothing and exits 0. After this run, exit 2
means usage and nothing else, every message says what to do next, the help and
guides match the binary, `doctor` tells the truth about the plugin, the metrics
order runs and count first-pass and convergence correctly, one frontmatter
reader and rewriter handles CRLF and BOM everywhere, and the README is a
newcomer's page. The suite gets faster first, so every later iteration's check
costs less. Refactors with no behaviour change are B12's.

The blind spot: each brief added commands, flags and records without anything
that held the help, the guides and the README to them, and errors defaulted to
exit 2 because a bare `return err` is the easy path.

## Why this shape, and what was rejected

Decided with the operator on 2026-10-05. **Do not re-litigate these** — the
planner inherits them.

- **Everything a user meets here; code health in B12.** Behaviour-preserving
  refactors are judged only by the check, and mixing them with contract changes
  makes every check failure ambiguous. The one refactor here is the frontmatter
  reader and rewriter, because the CRLF bugs are its symptoms. *Rejected:* one run
  of about 25 tasks; three runs.
- **Test speed first.** The repository's `go` check takes about nine minutes
  after every iteration; a faster `cmd/vloop` package pays off in this run.
- **Exit 2 is opt-in, for usage only:** an unknown command or flag, a wrong
  argument count, an invalid value for a flag or field. Everything else that
  fails exits 1. Announced in a "What changed in 2.0" section. *Rejected:*
  fixing only the known misclassifications (the default stays a trap); a code per
  error class (new behaviour scripts would have to learn).
- **The README follows the v1 review's outline, updated for v2**, and is
  rewritten last, so it describes what the run built. No command table: the
  generated `docs/guide/commands.md` is that. *Rejected:* a 60-line stub; patching
  today's structure.
- **Nothing global.** `vloop plugin path` outside a repository refuses rather
  than writing anywhere but a repository (C-1).

## Behaviour contract

Messages below are exact where quoted; `<…>` marks a value. A refusal is one
line on stderr starting with `vloop: `; `doctor` and `run`'s preflight print
their checks first, then that line.

### Q1 — the suite is faster

**Required.** In `cmd/vloop`, every test that builds its own temporary
repository and changes no process-wide state (environment, working directory)
runs with `t.Parallel()`; a test that must stay serial says why in a comment.
`go test ./cmd/vloop/` takes at most **half** its time at the base, on the same
machine — measured once, at verification (the real-data check), **never by a
gate**: every done gate re-runs each iteration, and a gate that times the suite
would cost more than it saves. Q1's gate judges a contract a session can show
quickly; the review judges from the diff that the tests that may run in parallel
do. `TestWorkedExampleB6RealData` clones the
repository's **HEAD**, not its working tree, and no longer fails when the
working tree changes while it runs.

### Q2 — exit codes

**Required.** Exit 2 only for: an unknown command or flag, a wrong argument
count, and an invalid value for a flag or a settable field (`config set`,
`task set`, `defect set`, `intervention set`, `--by` and the like). Every other
failure exits 1. These exit codes change, and the guide says so:

| Today | After |
| --- | --- |
| `vloop run docs/briefs/nope.md` exits 2 | exits 1 |
| `vloop brief check missing.md` exits 2, "not a loop brief" | exits 1, `vloop: no such file: missing.md` |
| `vloop intervention set <id> decided 5` exits 1 | exits 2 (an invalid value) |
| `vloop intervention set <id> recommended 9` exits 1 | exits 2 |
| any other non-usage error that exits 2 | exits 1 |

### Q3 — messages say what to do next

**Required.**

- `vloop: no plan — vloop run <brief> makes one` (was `no plan: …`).
- `vloop: no task T<n> — vloop task list shows the plan's tasks`.
- `vloop metrics <name>` for a brief that does not exist:
  `vloop: no brief <name> — vloop brief list shows the briefs` (a brief with no
  runs keeps `no runs for <name>`).
- `-C <dir>` naming no directory, for every command:
  `vloop: -C <dir>: no such directory` (exit 1).
- A command that needs git outside a repository: `vloop: <dir> is not a git
  repository` — no raw `git … exit status 128` text.
- A plan that is not valid JSON: `vloop: .vloop/state/state.json is not valid
  JSON (line <l>, column <c>)`; a plan that fails its schema: `vloop:
  .vloop/state/state.json is not a valid plan — vloop task validate lists the
  problems`. `status` and `status --json` exit 1 on either (`{"error": …}` under
  `--json`). `task validate` and `schema validate` print `<path>: not valid JSON
  (line <l>, column <c>)` with no empty field.
- `vloop brief check` with only drafts: `nothing checked: <n> draft brief(s)
  skipped` (exit 0), not `briefs ok`.
- `vloop plugin path` outside a vloop repository: `vloop: not in a vloop
  repository — run vloop init first` (exit 1), and nothing is written.
- `vloop intervention show` prints the `schema` and `options` lines and omits an
  empty `brief`; `vloop intervention migrate --dry-run` prints repo-relative
  paths.

### Q4 — help

**Required.** Shorts: `run` "Plan a brief and work it, task by task, on a work
branch"; `brief` "Write, check, list and close loop briefs"; `task` "Show,
amend, gate and reset the plan's tasks". Verbs are consistent: `List …` for
lists, `Show …` for one thing or a report, and every `set` Short names its
settable fields as a sentence. `Long` help for the root (what a brief is, the
loop in three sentences, where to start: `vloop init`, `vloop brief new`), `run`
(how the brief is chosen, what a run does, how to resume, the exit codes and
where they are documented), `brief`, `task`, `metrics`, `defect` and
`intervention`. `docs/guide/commands.md` is regenerated from them.

### Q5 — the guides

**Required.** `docs/guide/concepts.md`: the exit-code table states 1 as
"problems or failure, including a failed plan session or a mid-run error" and 2
as "usage" (for `vloop run`, 2 also "blocked", R-3, unchanged); a **"What changed
in 2.0"** section: the gate model (`state/v2`, gate folders, the gate review,
`[[check]]`), `intervention/v2` and `migrate`, `metrics/v2`, and the exit-code
change of Q2; the doctor check list in its real order, including `checks` and
`self-hosting`; the plugin's five skills. `configuration.md`: environment names
turn `.` and `-` into `_`. `metrics.md`: the synopsis gains `--workspace`,
`--interventions` and `metrics export`. Shell-loop references in the guides are
marked "legacy: the shell loop that built vloop's first briefs, in this
repository only", not removed. The README claim of "one line" follows the
qualified rule above.

### Q6 — `vloop doctor`'s plugin check

**Required.** It passes with `the plugin is supplied by vloop run
(--plugin-dir); for an interactive session: claude --plugin-dir "$(vloop plugin
path)"` when no marketplace plugin is enabled; reports a vloop plugin that is
installed but disabled as `installed but disabled — claude plugin enable
vloop@vloop`; and reports a failing `claude plugin list` as a warning naming
the error instead of swallowing it.

### Q7 — metrics that order and count right

**Required.** New run folders are named in UTC; existing folders keep their
names and are ordered by their records' timestamps, so a DST fall-back reorders
nothing. The convergence ratio divides this run's iterations by the tasks this
run closed. A task that was reverted by a gate regression and redone is not
first-pass.

### Q8 — one frontmatter reader and rewriter

**Required.** One package reads and rewrites the frontmatter of briefs, defects,
interventions and run records, used by every command that does: a leading BOM is
ignored and preserved, CRLF files are read and rewritten in CRLF, no write leaves
mixed line endings, and a rewrite touches only the lines it changes. `defect set`
and `intervention set` on a CRLF record work. `brief close` rewrites only the
first `**Status:**` line it means to, as its comment says, and reads the clock
once.

### Q9 — the rest of the review's correctness findings

**Required.** A report the driver fails to copy, and a restore that fails, are
errors reported as such, never "restored". The plan is synced to disk before it
replaces the old one. The trust lookup in `~/.claude.json` compares paths with `/`
separators, and case-insensitively on Windows and macOS. The pre-commit hook
check finds the hooks directory with `git rev-parse --git-path hooks`, and on
Windows counts a hook by its presence. `cmd/gendocs` refuses an argument that
starts with `-`; the tracked `--help` file at the root is deleted. The `CLAUDE.md`
section `vloop init` writes lists the session kinds plan, gate review, work and
review, and names `/vloop:operate` as the operator's playbook.

### Q10 — the evals

**Required.** `plan-checks-its-gates`' fixture grader judges the gate folder's
files themselves (a grader that reads them, not a trace that ends before they
are written): a gate expecting the configured punctuation from a fixture whose
key sits after `[style]` fails it, and a negative fixture inside `[style]`
expecting the default does not (D20261004-1309). `operate-proposes-options`'
judge graders judge only the options offered for the disputed gate, not other
problems the answer raises (D20261005-0757). The run record states both cases'
scores and spend, run by the operator.

### Q11 — the README, last

**Required.** At most 200 lines, in this order: what vloop is; prerequisites (Go
as in `go.mod`, git, the `claude` CLI, workspace trust); install (`go install` at
a release tag; the plugin through `--plugin-dir` while the repository is
private); a quickstart (`vloop init`, a `[[check]]`, `vloop doctor`, `vloop brief
new`, `brief check`, `vloop run`, `vloop brief close`); the loop in one
paragraph (plan, gate folders, the gate review, work, gates, checks, review, one
commit); the everyday commands in a short list pointing at
`docs/guide/commands.md`; exit codes in brief, pointing at the concepts guide;
the guides; "What changed in 2.0". No command table. The README test's cap stays.

### The domain, updated

`docs/domain/platform/platform-context.md`'s conventions read: exit `0` ok, `1`
problems or failure, `2` usage only; a refusal is one stderr line starting
`vloop: `, after any checks `doctor` or a preflight prints. Nothing else in the
domain changes.

### Decided here, because the cited documents leave it underdetermined

- "Invalid value" is the validation of a flag or field's value against its
  vocabulary or format; a missing file, brief, task or record is not usage.
- The speed target is relative (half the base, same machine), so no absolute
  number decays with the hardware, and it is measured at verification only.
- UTC applies to new run folders only; renaming existing ones would break the
  run records that cite them.
- Messages keep the `vloop: ` prefix and state the next command, not a sentence
  of advice.

### Violations the review must rule on

- A non-usage failure that still exits 2, or a usage error that exits 1.
- A message that differs from the one quoted here.
- A behaviour change beyond the findings (B12 is refactors with no behaviour
  change; anything new waits for the triage after 2.0.0).
- A refactor from B12's list folded in: the git wrappers, the duplicated env
  filters, `planSHA`, `driver.counts`, the budget keys, the id generators, long
  functions.
- A test made parallel that changes the environment or working directory.
- The README over 200 lines, or with a command table.

## Worked example

With a fresh build, in temporary directories:

```
vloop -C /nonexistent status         -> vloop: -C /nonexistent: no such directory      exit 1
vloop run docs/briefs/nope.md        -> vloop: … (unchanged text)                       exit 1
vloop brief check missing.md         -> vloop: no such file: missing.md                 exit 1
vloop --bogus                        -> unknown flag (usage)                            exit 2
in an init'd repo with no plan:
  vloop task show T1                 -> vloop: no plan — vloop run <brief> makes one   exit 1
with a plan of T1:
  vloop task show T99                -> vloop: no task T99 — vloop task list shows the plan's tasks   exit 1
vloop metrics nope                   -> vloop: no brief nope — vloop brief list shows the briefs      exit 1
plan "{bad": vloop status            -> vloop: .vloop/state/state.json is not valid JSON (line 1, column 2)   exit 1
plan {"version":"x"}: vloop status --json
                                     -> {"error": "… is not a valid plan — vloop task validate lists the problems"}   exit 1
only draft briefs: vloop brief check -> nothing checked: 2 draft brief(s) skipped       exit 0
outside any repo: vloop plugin path  -> vloop: not in a vloop repository — run vloop init first   exit 1; no .vloop/ created
not a git repo: vloop metrics        -> vloop: <dir> is not a git repository            exit 1
a CRLF defect: vloop defect set <id> status fixed
                                     -> exit 0; the file says status: fixed, every line still ends CRLF
a BOM + CRLF intervention: vloop intervention set <id> phase verify
                                     -> exit 0; BOM kept, CRLF kept
vloop intervention set <id> decided 5-> exit 2
cmd/gendocs --help                   -> refused; no file named --help written
vloop doctor, no marketplace plugin  -> ✓ plugin the plugin is supplied by vloop run (--plugin-dir); …
vloop --help                         -> says what a brief is and to start with vloop init
```

The gates thread the values they compute (paths, ids) rather than hardcoding
them.

**Real-data check.** On this repository, `vloop metrics --json` for every
consumed brief (B1–B10) equals beta.2's, except first-pass and convergence where
a task regressed and was redone; the run record lists each changed number with
its brief and task. `vloop defect list`, `intervention list` and `brief list`
read every record as before. `go test ./cmd/vloop/` on this repository takes at
most half its base time.

## Out of scope

- **B12, code health with no behaviour change:** one git wrapper (seven today),
  the three env-filter copies, `planSHA` duplicated, `driver.counts`, budget keys
  in three places, the id generator in three copies, long functions,
  `TestMain`'s panics, a Windows run harness.
- **The triage after 2.0.0** of defects and interventions into skill changes and
  repo-specific guidelines.
- New commands or flags; a CHANGELOG file; publishing a marketplace or a GitHub
  release; error codes per class.
- Renaming existing run folders; rewriting past records.

## Constraints

- Go as pinned in `go.mod`; no new dependencies. Every gate builds for
  `windows` and `linux` as well as the host; OS-specific behaviour (path
  comparison, hook detection) is a pure function tested on every OS.
- Gates run on macOS's BSD tools: no empty alternatives in `grep -E`, no
  `sed -i` without a suffix, no `\+` or `\|` in basic regexes, no `date -d`.
  A scratch directory is `mktemp -d "${TMPDIR:-/tmp}/gate.XXXXXX"`.
- Sessions never move refs and write nothing under `.vloop/` but `.vloop/tmp/`
  (S-4): no task's work, and no gate, may require a session to change this
  repository's records, config or state. Tests build their repositories in
  temporary directories and address them with `git -C`.
- **The gate model applies** (`plugin/skills/plan/SKILL.md`): each gate judges
  this brief's contract by running the built binary, with its judge in the
  verify or its gate folder; no gate runs the repository's tests — this
  repository's `[[check]]` does, after every iteration.
- **No task may weaken a check to pass.** These earlier tests **must** change,
  and only as stated:
  - every test that asserts exit 2 for a failure Q2 makes exit 1, or exit 1 for
    an invalid value Q2 makes exit 2 — each listed in its task's notes;
  - every test that pins a message Q3 or Q4 changes, a Short or the help;
  - `docs/guide/commands.md`'s staleness test (regenerate, as always);
  - `TestWorkedExampleB6RealData` (Q1);
  - the README tests: the completeness checks stay in the guides; the cap stays;
  - tests that pin metrics affected by Q7, with the changed numbers listed;
  - `internal/install` tests that pin the `CLAUDE.md` section's text.
- Evals are the skills' gates: the run record states the two changed cases'
  scores and spend, run by the operator.
- Repo-relative paths everywhere. No absolute paths in any file or commit
  message.
