## Executive summary

`go install github.com/mvelosop/vloop/cmd/vloop@v0.15.0-rc.2` fails: the
module proxy cannot build the module zip, because 11 committed paths hold a
directory named `it's repo`, and Go rejects `'` in a module file path. Eight
are B37's kit fixtures and goldens under
`tools/copilot-acceptance/kit/testdata/`, three are B37's gate fixtures
under `.vloop/state/gates/`. Nothing before the tag looked at the module
zip: not the checks, not the gates, not verify, not `tools/release prepare`.

**The goal:** the repository holds no path the module zip rejects, a test in
`go test ./...` fails the day a file path Go's module rules reject is
added, `release prepare` refuses to
open a release whose module does not zip, so v0.15.0-rc.3 installs; and
`go.mod` retracts v0.15.0-rc.2, which takes effect once v0.15.0 is out.

- **Z1 — the kit's fixtures without `'` in a path.** The kit's tests still
  run the probes in a directory named `it's repo`, made at test time; the
  goldens' bytes do not change.
- **Z2 — `release paths`, and a test that fails on a path Go's module
  rules reject** (`module.CheckFilePath`). Every tracked or untracked, not ignored, file of the
  repository, checked with Go's own rules; the `go` check runs the test
  after every task of every run, which closes the blind spot.
- **Z3 — `release prepare` refuses a module that does not zip.** It builds
  the zip from git as the proxy does, before writing anything.
- **Z4 — `retract v0.15.0-rc.2` in `go.mod`.**

What does not change: the kit's commands, its output, what its tests assert;
`release publish`; every other refusal of `prepare`.

## What it is

After the run, no path in the repository breaks `go install`, and two
guards keep it so: one in the `go` check (`go test ./...`, after every
iteration), one at the release.
The defect got through because every check runs on a checkout, where any
file name works; only the proxy builds the zip, after the tag is pushed.

## Why this shape, and what was rejected

Decided on 2026-11-06. **Do not re-litigate these** — the planner inherits
them.

- **Fix forward with v0.15.0-rc.3, and retract rc.2.** A pushed tag the
  proxy has seen cannot be fixed in place. Go reads retractions from the
  go.mod of the latest release (v0.14.0 today), so the line only takes
  effect with v0.15.0; it is written now so it cannot be forgotten. The
  proxy lists no v1.0.0: `go list -m github.com/mvelosop/vloop@latest`
  gave v0.14.0 on 2026-11-06.
  *Rejected:* deleting and re-pushing the rc.2 tag — the proxy and the
  checksum database may keep the first one.
- **The kit keeps testing a directory whose name needs quoting.** That is
  what the `it's repo` fixture is for: the probes' Python quoted it with
  `repr`, and the Go port must still be seen to.
  *Rejected:* renaming the directory to a plain name everywhere — it drops
  the case the fixture exists for.
- **Go's own rules, from `golang.org/x/mod`** (`module.CheckFilePath` for a
  path, `zip.CreateFromVCS` for the release), not a hand-written list of
  characters. The rules also cover reserved Windows names; a copy drifts.
  The test checks paths only: the zip's other limits (case-fold
  collisions, file sizes, `go.mod`) are Z3's, at release time.
  *Rejected:* a `grep` for `'` in `git ls-files` — it catches this defect
  and no other.
- **The guard is a test, not a new `[[check]]`.** `go test ./...` already
  runs after every iteration of every run; a test is seen to fail on a
  fixture.
  *Rejected:* a check in `.vloop/config.toml` — sessions cannot edit
  `.vloop/`, and a check cannot be planted.
- **The three `.vloop/state/gates/` paths are not a task.** The plan
  commit of this run replaces `.vloop/state/gates/` (B37's plan commit
  removed B36's gate files the same way), so they are gone before T1.

## Behaviour contract

### Z1 — the kit's fixtures without `'` in a path

**Defect.** `tools/copilot-acceptance/kit/testdata/` commits 8 paths under a
directory named `it's repo`: `probes/hook/it's repo/.keep`,
`probes/probe/it's repo/.keep`, and
`hooks/vloop-fence.json` in `golden/<case>/it's repo/.vloop/tmp/home` for the
cases `hook-forms`, `hook-forms-second-review`, `hook-fail-missing`,
`hook-fail-exit1`, `hook-fail-notjson`, `hook-fail-timeout`.

**Required.**

- No path under `tools/copilot-acceptance/` holds `'`.
- In the committed tree the directory is named `@REPO@`, the way `@DIR@`
  stands for the temporary directory: `probes/hook/@REPO@/.keep`,
  `probes/probe/@REPO@/.keep`, and `hooks/vloop-fence.json` in
  `golden/<case>/@REPO@/.vloop/tmp/home` for the six cases.
- The fixtures `probes/hook` and `probes/probe`, copied for a test, still
  give a directory named exactly `it's repo` (a path component `@REPO@`
  becomes `it's repo` in the copy), so the logged session's working
  directory `@DIR@/it's repo` exists as before.
- The hooks file the kit writes, `hooks/vloop-fence.json` in
  `it's repo/.vloop/tmp/home`, is still compared,

  golden's bytes are today's.
- `gen.sh`, run as its header says on the Python of B37's starting point
  (`d7b9cbb5`; B37 deleted it), writes the goldens at their new paths, and
  its output equals the committed goldens. Its header names `d7b9cbb5` as

- Every other file of `testdata/` but `gen.sh` keeps its path and its
  bytes.

### Z2 — `release paths`, and a test that fails on a path Go's module rules reject

**Required.** A function of `tools/release` lists the repository's files with
`git ls-files -z --cached --others --exclude-standard` (run with `git -C`
on the repository's top directory; `-z`, so no path comes out quoted) and checks each path with
`module.CheckFilePath` from `golang.org/x/mod` v0.37.0. It fails when one
or more are rejected, with one line per rejected path, in the order git
lists them:

```
<path>: <the error CheckFilePath returns>
```

`go run ./tools/release paths`, in the repository it is started in, prints
those lines on stdout, then on stderr
`release: the module zip rejects <n> path(s)`, exit 1; with none, it prints
nothing, exit 0. Given any argument, it prints `usage: release paths` on
stderr, exit 2. When git fails (started outside a repository, for
instance), stderr holds `release: <git's error on one line>`, exit 1. The
usage line of `tools/release` gains `paths`:
`usage: release notes <from> <to> | paths | prepare <version> [--dry-run] | publish <version> [--wait <duration>] [--dry-run]`.
`TestRepositoryPaths` in `tools/release` runs the function on this
repository and fails with the same lines; `TestPaths` holds the cases
below.

for instance

```
it's repo/.keep: malformed file path "it's repo/.keep": invalid char '\''
```

The function takes the directory as a parameter; the cases, each a fixture
repository in a temporary directory:

- a committed `it's repo/.keep` → that line;
- an untracked, not ignored `a'b.txt` → `a'b.txt: malformed file path "a'b.txt": invalid char '\''`;
- the same `a'b.txt` listed in the fixture's `.gitignore` → no line;
- a fixture with only `go.mod` and `x.go` → no line.

The test that checks this repository skips, saying why, when
`git rev-parse --show-toplevel` fails or the top directory's `go.mod` does
not declare `module github.com/mvelosop/vloop` (run from the module cache,
for instance). An untracked, not ignored file with a rejected name in a
developer's checkout fails it; that is intended.

### Z3 — `release prepare` refuses a module that does not zip

**Required.** `prepareChecks` gains one check, after "main is not
origin/main" and before the configured checks run. It builds the module zip
of `HEAD` for the module path `go.mod` names and the version asked, with
`zip.CreateFromVCS` from `golang.org/x/mod` v0.37.0, written to
`io.Discard`. It writes nothing to the repository.

- When `errors.As` finds a `zip.FileErrorList` in the error
  (`CreateFromVCS` wraps it), stderr holds one line per rejected file, `<path>: <error>` with the path relative to the
  repository, then
  `release: the module zip rejects <n> path(s)`; exit 1.
- Any other error: `release: the module does not zip: <the error on one
  line, every occurrence of the repository's absolute directory replaced
  by .>`; exit 1.
- `--dry-run` runs it, as every other check.
- In a linked worktree (`git worktree add`), `CreateFromVCS` finds no
  `.git` directory and `prepare` refuses with
  `release: the module does not zip: create zip from version control system .: could not find a recognized version control system at "."`;
  `prepare` runs from the main checkout, as it does today.
- Neither the configured checks nor `claude plugin validate` run after
  this refusal.

`tools/release/README.md`'s `prepare` paragraph names the check in its list:
"…`main` clean and equal to origin, the module zip of `HEAD`, the config's
checks…", and a `## paths` section says what `paths` prints and when it
exits 1.

### Z4 — the retraction

```
// downloaded.

```

## Worked example

`<rel>` is the release tool built from the tree:
`go build -o <tmp>/release ./tools/release`. `<F>` is a fixture repository
made in a temporary directory: `git init -b main`, a `go.mod` holding
`module example.com/m` and `go 1.27`, one commit, a bare repository in
another temporary directory as its `origin`, `main` pushed to it.

```
<rel> paths                                    (in this repository)
  -> no output                                                  exit 0

<F> plus a committed it's repo/.keep; <rel> paths in <F>
  -> stdout: it's repo/.keep: malformed file path "it's repo/.keep": invalid char '\''
     stderr: release: the module zip rejects 1 path(s)          exit 1

<F> plus an untracked a'b.txt; <rel> paths in <F>
  -> stdout: a'b.txt: malformed file path "a'b.txt": invalid char '\''
     stderr: release: the module zip rejects 1 path(s)          exit 1

<F> plus that a'b.txt listed in its .gitignore; <rel> paths in <F>
  -> no output                                                  exit 0

<F> plus a committed and pushed it's repo/.keep;
<rel> prepare v0.1.0 --dry-run in <F>
  -> stderr: it's repo/.keep: malformed file path "it's repo/.keep": invalid char '\''
             release: the module zip rejects 1 path(s)          exit 1
     and <F>'s `git status --porcelain` and refs unchanged

<rel> prepare v0.15.0-rc.2 --dry-run           (in this repository)
  -> stderr: release: v0.15.0-rc.2 is retracted in go.mod       exit 1

sh tools/copilot-acceptance/kit/testdata/gen.sh <py> <built vloop> <tmp out>
diff -r <tmp out> tools/copilot-acceptance/kit/testdata/golden
  -> no output                                                  exit 0
  (<py> holds report.py, hook.py and bypass.sh from
   `git show d7b9cbb5:tools/copilot-acceptance/<file>`)
```

The `<F>` lines need `git commit` and `git push`, which a verify session
cannot run: they are covered by `TestPaths` (the three `paths` cases) and
`TestPrepareRefusals` (the `prepare` case) in `tools/release`, which the
`go` check runs, and by the gates of tasks 2 and 3.
