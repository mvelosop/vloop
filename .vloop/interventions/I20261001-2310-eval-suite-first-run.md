the full eval suite's first run: every review case caught, the plan and work cases held back by the sandbox

**Trigger.** The operator approved the full suite at a $40 ceiling after the probe passed.

**Context.** 13 cases × 3 runs × 2 arms, `-j 2`, model claude-opus-5-5 (the calibration's baseline was sonnet): $17.97, 25 minutes, overall 0.89, mean delta over no plugin 0.85. Review: all nine cases FAIL the planted work in 27 of 27 runs and name the defect (`06` included); two runs (05, 07) lost only `verdict-validates`. The without-plugin arm scores 0 everywhere but `work-disputes-impossible-gate` (0.5). Plan and work: `plan-valid-state` 0.5 (never validated), `plan-checks-its-gates` 0.41, `language-es` 0.85, `work-disputes-impossible-gate` 0.92; nearly every loss is a `*-validates` grader or a judge reading a transcript in which no gate ran. Two environment causes, read from the report: (1) git cannot run in the sandbox: `/usr/bin/git` is the xcrun stub, whose cache write to `$TMPDIR` is denied, though Homebrew's git is first on the operator's PATH; (2) sessions run in don't-ask mode and use compound commands (`cat …; echo ---; git ls-files`) whose unrelated segments (`echo`, `ls`, `find`, `which`) are not granted, so they are denied, and after a few denials a session stops using Bash, `vloop schema validate` included. The run transcripts were not kept (no `--keep-temp`).

**Suggested.** One diagnostic run of `plan-valid-state` with `--keep-temp` (about $0.5) to read the trace's PATH and every denial, then fix in the environment (a real git first on the sessions' PATH) and the cases (grant the read-only commands sessions reach for), and re-run only the plan and work cases.

**Decided.** The operator approved the diagnostic run (2026-10-02): `plan-valid-state`, 1 run, no baseline, `--keep-temp`, $0.37, score 0.50 (the same two `*-validates` graders lost). The trace: the session's first Bash call was one compound command (`cat …; echo ----; cat CLAUDE.md; echo ----; git ls-files; git rev-parse HEAD; vloop config get shell; echo "areas=[$(vloop config get areas)]"`); don't-ask mode denied it whole with a message that reads as "Bash is denied", and the session never tried Bash again. A Grep outside its working directory (into the plugin's source) was denied too. It read the repo with Read and Glob, wrote `state.json`, and said it could not check it. Git was never reached, so the xcrun-stub cause is neither confirmed nor ruled out. The production driver runs sessions with `--permission-mode auto` under the fence, whose allow list is wider (`ls`, `head`, `tail`, `find`, `wc`, `jq`, `git show`, `vloop task validate`, `vloop task gate`); the cases grant a narrower set in don't-ask mode, so the evals are stricter than a real run. The operator approved the fix and a rerun: every case now grants the fence's allow list plus `echo`, `git ls-files`, `grep`, `sh`, `chmod`, `test`, `vloop task`, held by `TestEvalGrantsCoverFence` (17f260e). Rerun of the four plan and work cases, 3 runs × 2 arms, $6.94: `plan-valid-state` 0.50, `plan-checks-its-gates` 0.33, `language-es` 0.78, `work-disputes-impossible-gate` 0.92 — no better. Single commands now run; compound ones (`for` loops, `$(…)`, `;` chains with ungranted parts) are still denied. The traces show two causes underneath: (1) the sessions run a stale `vloop` (`~/go/bin/vloop`, built 2026-09-29: `unknown command "schema"`, `"task"`, `"status"`, `unknown config key "shell"`) — the sandbox denies reads under `/private/tmp` and `/Users`, allowing back only a few bin directories (`~/go/bin`, `~/.local/bin`, nvm's), so the freshly built binary first on PATH in the scratchpad is unreadable and the old one wins; (2) git is the xcrun stub (`git: error: couldn't create cache file`). The first suite's validation losses, review cases included, have the same causes. The operator approved `go install ./cmd/vloop` (replacing the stale `~/go/bin/vloop`) and a probe: `plan-valid-state`, 1 run, no baseline, $0.40, score 0.80 — `state-validates` and `task-validate` pass. Two environment causes remain, both in the trace: the sessions inherit the operator's `TMPDIR` (`/var/folders/…/T`), which the sandbox denies, so the gate's `mktemp -d` fails; and `git` resolves to the xcrun stub `/usr/bin/git`, which cannot write its cache there and finds no Command Line Tools (`xcode-select: Failed to locate 'git'`), though Homebrew's git is first on the operator's PATH. The one grader lost, `plan-quality` (judge 0/3), reads a sound plan: its "no absolute path anywhere" clause is met literally by `#!/bin/sh` in an acceptance criterion and `cd /` in the verify — a grader wording defect, not the plan's. Three throwaway probe cases in a scratch copy of the plugin (haiku, about $0.13 in all) showed the real causes. The Command Line Tools are installed; `DEVELOPER_DIR` does not help the stub. Inside the eval sandbox `$PATH` lists `/opt/homebrew/bin` before `/usr/bin`, yet the shell resolves bare `git` to `/usr/bin/git` (`type -a git` lists only it, after `hash -r` too), and the stub fails because it writes its cache to macOS's per-user temp directory (`/var/folders/…/T`), which the sandbox denies whatever `TMPDIR` says. `env git`, `/opt/homebrew/bin/git` and `/Library/Developer/CommandLineTools/usr/bin/git` all work. `TMPDIR` is already a writable sandbox directory, but macOS `mktemp -d` without a template ignores it and uses the same denied directory, so a gate written with `mktemp -d` fails in the evals though it works in a real run. Next step pending the operator.

**What would automate it.** The eval tool reporting denied tool calls per run; a pre-flight case that runs `git status` and a compound command in the sandbox.
